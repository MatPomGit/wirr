Wirtualna i Rozszerzona Rzeczywistość · Lab 06

WiRR WebSim

Lokalny backend ROS 2 dla cyfrowego bliźniaka robota. Kontener generuje rzeczywiste komunikaty JointState, a Unity odbiera je przez rosbridge WebSocket.

Co działa

Oddzielne sesje zespołów, RRBot 2R i WiRR Arm 3R, stan LIVE/STALE, ruchy A–C, Home i Reset.

Gdzie działa

Na komputerze studenta lub serwerze w tej samej sieci. Nie jest to serwer chmurowy — GitHub Pages publikuje wyłącznie tę instrukcję.

Szybki start

  1. Zainstaluj Docker Desktop albo Docker Engine z Compose.
  2. Sklonuj repozytorium i przejdź do katalogu WebSim~.
  3. Uruchom kontener, pozostawiając terminal otwarty.
git clone https://github.com/MatPomGit/wirr.git
cd wirr/WebSim~
docker compose up --build

Unity na tym samym komputerze

W WiRR → Course Toolkit → Lab 06 ustaw:

ws://127.0.0.1:9090

Unity na innym komputerze

Ustal adres IPv4 serwera i otwórz port TCP 9090 w jego zaporze:

ws://ADRES_IP_SERWERA:9090

Kontrola ćwiczenia

W Unity wpisz kod zespołu (3–12 znaków: A–Z, cyfry, _, -), wybierz model, użyj Create / repair WebSim digital twin, uruchom Play Mode i kliknij Connect. Ruch w Unity musi wynikać z topiku /wirr/<SESSION>/joint_states.

/wirr/<SESSION>/joint_states   sensor_msgs/msg/JointState, 30 Hz
/wirr/<SESSION>/command        std_msgs/msg/String
/wirr/<SESSION>/status         std_msgs/msg/String
/clock                         rosgraph_msgs/msg/Clock

Bezpieczeństwo: nie wystawiaj portu 9090 do Internetu. Jeśli potrzebujesz połączenia spoza LAN, użyj odrębnego reverse proxy z TLS/WSS i kontrolą dostępu.
